# 2026-11-01 体验评审与已有领域首页补齐

本次按现有结构，把“首页”定义为每个领域路线中首个知识点的启蒙、进阶、深入三张页面。启动时自动补齐已有领域，并增加无需重启的 `python -m app.cli backfill-homepages` 命令。已生成的页面和已有任务直接复用；只有显式使用 `--retry-failed` 才重新排队失败的首页。

本地数据库已备份至 `/tmp/learnwise-before-homepage-backfill-20261101-171336.db` 后执行补齐：7 个已有领域、21 张首页入队。此前唯一一张已生成页面并非这些首页，因此本次没有重复生成该页面。这里只完成本地排队，网站服务运行后才执行生成；没有部署或修改线上数据库。`/tmp` 备份是临时副本，上线操作仍需使用服务器持久备份。

## 其余已修复问题

- 匿名用户可以查看预生成任务的等待页和完成后的页面；失败时明确引导登录重试。
- 失败页面重新打开时保留错误，用户点击重试才重新生成，避免刷新触发重试。
- 等待页区分排队、生成、额度暂停和网络重连。未开始的后台任务在额度耗尽时保留队列，次日额度恢复后继续。
- 地图档位标签区分“可学”和“准备中”，并解释未选择水平时的默认行为。
- 登录回跳保留当前档位查询参数，并限制回跳到站内页面。
- 诊断提交失败保留答案、提供再次提交按钮；不完整或越界的答案返回明确错误。
- 复习提交期间禁用全部评分按钮，避免快速连续点击重复提交。

## 验证与范围

验证使用临时数据库和模拟模型，不访问付费生成接口。

本次最终结果：21 项 Python 回归测试通过，2 组 Node 交互测试通过，完整 HTTP 用户流程通过，真实 Uvicorn 启停及 5 个公开页面 HTTP 检查通过；4 份样例校验、依赖检查和部署脚本语法检查均通过。本地队列最终确认仍为 21 个 queued 预生成任务，原有 1 张 ready 学习页保留。

- Python 回归测试覆盖旧库迁移、并发去重、优先级、首页补齐、失败重试、预算暂停与恢复、匿名等待、地图状态、登录回跳、诊断、闯关、卡片和复习。
- `tests/review_user_flow.py` 模拟“创建领域 → 等待 → 六档自选 → 九题诊断 → 学习 → 闯关 → 下一页 → 卡片 → 复习 → 费曼 → 问老师 → 反馈”的 HTTP 流程。
- `tests/test_learning_ui.cjs` 使用 Node 的 DOM stub 检查卡片未同步、失败、重试，以及闯关失败重试、陈旧响应隔离。
- 主要页面渲染后的内联脚本通过 Node 语法检查；`tests/smoke_server.py` 使用临时数据库运行真实单 worker Uvicorn，验证健康检查、主要公开页面与正常关闭。

这次没有做真实浏览器的视觉、触屏操作和邮件送达测试，不能据此认定移动端视觉或真实模型生成速度已得到验证。

## 后续优化建议

1. 在真实手机浏览器上检查长学习页、知识星图和小屏导航，优先处理遮挡、点击区域和滚动定位问题。
2. 首页未登录时保存已输入的主题和学习目标，登录后继续填写，减少重复输入。
3. 在学习页显眼位置显示下一页准备状态和入口，减少寻找“下一步”的成本；目前下一页入口在闯关结果中。
4. 部署后观察预生成命中率、实际等待时长和每日花费，再决定是否调整后台并发或提前生成范围。
