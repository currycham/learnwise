# 2026-10-31 学习页预生成

现有项目以 2026-10-22 的设计文档、学习页结构和实现为基线，当前 Git 仓库尚无提交历史。现有学习单元为“领域 × 知识点 × 内容档位”，一个知识点在每档只有一张完整学习页。

本次把“第 1 页”落实为领域路线中的首个知识点，在领域地图生成完成后排队生成启蒙、进阶、深入三张页面。地图仍可在页面生成完成前查看。部署后会给已有领域补齐缺少的首页任务。

打开已生成的页面时，假设当前知识点闯关通过，调用现有推荐算法，预生成下一推荐知识点的同档页面。只改变用于预测的进度副本；真实进度仍由原有闯关接口更新。已经掌握的节点会跳过，全部掌握后不再生成。页面生成完成不会继续触发后续页，用户实际阅读才触发下一页。

页面和任务的创建在 SQLite 同一事务中去重，兼容并发阅读和主动点击；主动点击会提升已有预生成任务的优先级。队列顺序为主动请求、预生成、跨领域联系，同优先级按入队顺序。运行中的任务不抢占，仍使用原有 JOB_CONCURRENCY 和单进程部署方式。

预生成复用原有生成流水线和全站每日预算，不计入用户个人主动生成配额。自动预生成不会重试失败页面，保留原有错误和手动重试入口。匿名访问已生成页面也会触发下一页预生成。

数据库迁移只为 jobs 表增加 priority 列和索引。页面唯一约束、内容 JSON、学习页模板、诊断、闯关、卡片、费曼、问老师接口和模型提示词沿用原实现。

验证使用临时数据库和模拟模型，覆盖旧库迁移、并发去重、优先级、首页补齐、重启恢复、推荐路径、匿名访问、错误隔离、预算失败、重试，以及学习页、地图、闯关、复习卡和健康检查。真实模型的耗时和线上服务器运行状态需要部署后观察，离线验证不代表它们已被测量。

本地验证结果：15 项回归测试全部通过；4 份 fixtures 页面结构校验通过；pip check 无依赖冲突；三个部署脚本的 Bash 语法检查通过。另使用临时数据库，以单 worker 的 Uvicorn 入口启动真实 HTTP 服务，首页、健康检查、登录、知识星图、关于页均返回 200，启动和正常关闭成功。没有调用付费模型接口或部署到线上。
