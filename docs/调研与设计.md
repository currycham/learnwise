# LearnWise 调研与设计（2026-10-22，草案）

> 一句话：输入你想学的任何领域，LearnWise 先画出这个领域的「知识地图」，判断你站在地图的哪里，再为你的下一步生成一页 30 分钟就能学完、学了真记得住的学习页。每一页都公开，所有人生成的页面连成一张越长越大的知识网络。

## 1. 这个 idea 成立吗

**成立，但不能做成“AI 一键生成一门课”。** 这一步已经很拥挤，而且做出来的东西大多“看完就忘”。

### 竞品一览

| 产品 | 做法 | 好的地方 | 不足 |
|---|---|---|---|
| Oboe（Anchor 创始人做的，2025-09 上线） | 一句话生成课程，多种格式：图文、播客、闪卡、测验、小游戏；后来加了按目标生成章节 | 多格式、生成快、课程可分享 | 评测普遍认为它不是导师、也不管掌握程度；没有水平诊断和复习 |
| NotebookLM | 上传资料 → 音频概览（双人播客）、思维导图、闪卡、测验 | 双人播客做得最好；有资料兜底不容易编 | 要自己找资料；一次性生成，没有学习路径 |
| ChatGPT 学习模式 / Gemini Guided Learning | 对话里苏格拉底式提问、分步引导 | 互动强、随问随答 | 聊完就散，没有结构、没有沉淀、没法分享给别人 |
| Google Learn Your Way（研究项目） | 把教材按年级和兴趣改写，同一内容出沉浸文本、带讲解的幻灯片、音频课、思维导图 | 证明了“同一知识按水平和兴趣改写”有效 | 只做已有教材，不对外开放任意主题 |
| Khanmigo / Duolingo / Brilliant / Math Academy | 固定课程体系 + 游戏化 / 掌握度 / 知识图谱 + 间隔复习 | 学习科学做得最扎实（尤其 Math Academy 的前置知识图谱 + 掌握学习） | 领域是固定的，不能“学任何东西” |
| ClearMath、Figmap、StudyLens 等小工具 | 概念关系图、前置知识检测、个人知识地图 | 已经有人在做“知识地图”这个形态 | 偏小众，多数只做图，不做学习内容 |
| 国内：豆包 / Kimi / 夸克等的学习功能、得到 | AI 答疑解题，或人工精品课 | 国内用户熟悉 | AI 类偏 K12 解题；得到是固定课程，贵 |

> 以上是 2026-10 的检索结果加已有了解，海外产品的功能和价格未逐一试用核实。

### 空白在哪

现有产品各占一角：**Oboe 能学任何东西但不管你学没学会；Math Academy 管学会但只有数学；ChatGPT 能陪聊但不留下东西。**

LearnWise 要站的位置：

1. **任意领域，但先画地图再动笔**：不是直接吐一门课，而是先拆出领域的知识点和前置关系，学习者永远知道“我在哪、下一步学什么、为什么”。
2. **按水平生成，而且对水平诚实**：不只看你自选的标签，几道诊断题定位到具体知识点。
3. **学习科学是页面结构，不是营销词**：每个模块对应一条有证据的学习原理（见第 4 节），像 ReadWise 那样把方法“做进页面里”。
4. **生成的页面是公共资产**：像 ReadWise 的书库，一个人生成，所有人能学；页面之间连成知识网络。这也是成本能摊薄、能做 SEO 和公众号传播的原因。

### 风险

- **内容准确性**：书至少有原文可查，“任意领域”没有天然的资料边界，理工科公式、代码、医学法律尤其容易出错。→ 沿用 ReadWise 的“先检索再动笔、生成和质检分开”，并对高风险领域加限制（见决策 7）。
- **留存**：学习类产品普遍是“三天热度”。→ 复访靠间隔复习提醒和“点亮地图”的进度感，不靠打卡焦虑。
- **页面同质化**：通用模型写出来的讲解都差不多。→ 差异化在结构（诊断、地图、费曼、复习）和互动，不在文字本身。

## 2. 从你已有的产品里学到什么

### ReadWise：参考思路，代码自己写

LearnWise 是独立产品，只借鉴 ReadWise 的做法，不复制它的代码。

| ReadWise 的做法 | LearnWise 怎么借鉴 |
|---|---|
| 一本书 = 一份 60 分钟回顾页 | 一个知识点 = 一页约 30 分钟的学习页（一个番茄钟 + 休息） |
| 推荐 / 检视 / 分析（知识块）/ 检测 / 内化 / 问作者 | 几乎一一对应：钩子 / 地图定位 / 知识块 / 闯关 / 费曼与迁移 / 问老师 |
| 先检索 → 资料评估 → 生成 JSON → schema 校验 → 质检 → 内容安全 → 入库 | 同样的阶段划分，多加一步“领域地图”生成 |
| 模型只输出数据，模板渲染页面 | 同样的原则；以后做小程序/App 用同一份数据 |
| 生成失败自动换备用模型；每次调用记账；每日成本上限 | 同样要有 |
| 书库公开，按“能解决什么问题”分类 | 领域库公开，按“你想做成什么事”分类（如“想转行做数据分析”“想看懂财报”） |
| 书籍网络：五类联系、3D 星图 | 知识网络：节点从“书”变成“知识点”，边多了“前置”这种有方向的关系 |
| 双人播客（咖喱、路亚） | 可选模块：模型先判断这个知识点值不值得做播客，值得才生成 |
| 积分、等级、首位生成者被别人学完得积分 | 规则类似，以后和 ReadWise 打通（统一账号是主 agent 的事） |
| `fixtures/` 人工整理的样例页作为质量基准 | 动手写代码前，先人工打磨 2–3 份样例页 |

### 其它产品的共同理念

- **SaveWise「规则算数，AI 说话」、InvestWise「先自己判断，再看 AI」**：LearnWise 对应的原则是“**先自己想，再看答案**”——主动回忆、费曼讲解、预测题都要求先作答再展开。掌握度、复习间隔用确定性算法（FSRS）算，AI 不拍脑袋。
- **InvestWise「提问而不是给答案」**：“问老师”默认苏格拉底式，先反问再提示，不直接给答案（可以切换）。
- **可追溯**：每页附来源；模型编造的来源丢弃。
- **国内部署、不用境外 CDN、页脚备案号**：照旧。

### learning_agent：思路可借鉴，代码基本过时

可以借的：

- **6 级知识水平**（no_knowledge / basic / beginner / intermediate / advanced / research）：和你这次想的标签几乎一样，可以直接用作自选标签。
- **按水平切换学习模式**：知识获取（零基础、入门）→ 实践应用（初学、中级）→ 突破创新（高级、研究）。这个思路是对的，正好对应学习科学里的“专长逆转效应”（新手需要讲解和范例，专家反而被讲解拖慢，需要问题和争议）。
- **CodeRunner**：编程类知识点在页面里直接跑代码，后期可以加。
- **回答要带引用、按水平调深浅**的系统提示。
- **成就类型**（连续学习、探索领域数、测验成绩）。

过时的：Next 14 + FastAPI + PostgreSQL + Redis + OpenAI + Vercel/AWS 的架构，不适合国内单机部署，也和 ReadWise 那套已经跑通的技术栈重复；页面里大多是写死的模拟数据，没有内容生成流水线。**建议不在这个仓库上继续，只把上面几点思路搬过来。**

## 3. 核心设计：领域地图 + 知识点学习页

“任何领域”的最大难点是**粒度**：“机器学习”塞不进一页，“梯度下降”一页刚好。所以分两层：

```
用户输入：「我想学 机器学习」+ 目的（可选，如“能看懂论文”）
        │
        ▼
① 领域地图（一次生成，公开复用）
   15–40 个知识点，标出前置关系、所属阶段（入门 / 进阶 / 深入）、预计时长
        │
        ▼
② 定位水平
   自选标签（完全不懂 / 听说过 / 入门 / 能用 / 熟练 / 专家）
   + 可选 5–8 道诊断题（每题挂在一个知识点上，答对就往后跳，答错就往前探）
   → 地图上点亮“已掌握 / 不牢 / 未学”，给出“从这里开始”的建议路径
        │
        ▼
③ 知识点学习页（按“知识点 × 内容档位”生成，公开复用）
   约 30 分钟，学完闯关，进入复习队列
        │
        ▼
④ 间隔复习 + 地图点亮 + 下一个知识点
```

### 内容档位：6 个标签 → 3 档内容

自选标签保留 6 档（贴近用户的自我描述），但**生成的页面只分 3 档**，否则同一个知识点要生成 6 份，公开复用也会被打散：

| 档位 | 对应标签 | 页面侧重 |
|---|---|---|
| 启蒙 | 完全不懂、听说过 | 故事和类比开场，生活例子，少术语，先建立直觉 |
| 进阶 | 入门、能用 | 精确定义、范例 → 逐步撤掉提示的练习（渐隐范例）、常见误区 |
| 深入 | 熟练、专家 | 边界条件、流派之争、前沿和原始文献、反例；讲解少，问题多 |

### 学习页的模块

每个模块都对应一条学习原理（主要来自《学习之道》和认知科学里证据较强的结论）：

| 模块 | 时长 | 做什么 | 依据 |
|---|---|---|---|
| 钩子 | 2′ | 一个故事、悖论或真实问题，引出“为什么要学它” | 好奇心驱动记忆；故事比条目好记 |
| 先猜一猜 | 1′ | 学之前先答 1–2 道预测题，答错也没关系 | 预测/生成效应：先尝试再学，记得更牢 |
| 地图定位 | 1′ | 它在领域地图的哪里、前置是什么、学完能解锁什么 | 先看全局再学细节（《学习之道》的“组块”自上而下） |
| 知识块 ×3–5 | 15′ | 每块：一句话核心、讲解、一个类比、一个例子、一张图、一个误区；读完马上 2 道主动回忆 | 组块；双重编码（图 + 文）；具体到抽象；主动回忆胜过重读 |
| 练习 | 5′ | 进阶档：范例 → 半提示 → 独立做；深入档：开放问题 | 刻意练习；渐隐范例 |
| 闯关 | 4′ | 8–10 道题，题目和本页及前置知识点交错出现，答错指回对应知识块 | 交错练习；检索练习 |
| 费曼 | 3′ | 用自己的话把它讲给一个 12 岁孩子听（打字或语音），AI 对照要点打分，指出漏了什么、哪里讲错了 | 费曼学习法；自我解释 |
| 迁移 | 1′ | 这个知识能用在你的哪件事上（模板引导） | 精细化加工，联系自己 |
| 休息提示 | — | 学完提醒离开屏幕 5 分钟，让“发散模式”接手 | 《学习之道》专注 / 发散模式 |
| 播客（可选） | 8–12′ | 咖喱和路亚把这个知识点聊一遍，适合通勤先听 | 多通道；降低开始门槛 |
| 问老师 | 随时 | 以本页为上下文，默认苏格拉底式追问 | 苏格拉底法 |

页面结束后，本页的主动回忆题自动进入**复习卡片**，按 FSRS 算法排期（1 天、3 天、1 周……），到期发邮件或站内提醒。复习时交错混入同一领域其他知识点的卡片。

### 游戏化：让进度感来自“学会了”，不是“打卡了”

- **地图点亮**：领域地图一开始是雾，学完一个知识点并闯关及格就点亮一格；复习逾期的格子会慢慢变暗。这是最核心的游戏化，和学习效果直接挂钩。
- **领域 Boss 关**：一个阶段的知识点都点亮后，开放一场综合挑战（交错题 + 一道开放题）。
- **积分和等级**：沿用 ReadWise 的规则和上限，最好两边共用一个积分账户。
- **首位生成者奖励**：你生成的领域地图、学习页被别人学完，你得积分（ReadWise 已有）。
- **不做**：连续打卡惩罚、排行榜比学习时长——会鼓励刷时长而不是学会。

## 4. 知识网络

ReadWise 的书籍网络节点是“书”，LearnWise 的节点是“知识点”。

- **节点**：知识点（全站唯一，规范名 + 别名表，例如“梯度下降 / Gradient Descent”）。一个知识点可以属于多个领域地图（“贝叶斯定理”同时在概率论、机器学习、医学统计里）。这是网络能越长越大的关键：不同人学不同领域，会在共享的知识点上汇合。
- **边**：
  - **前置**（有方向）：学 B 之前要先懂 A。只在领域地图里生成，驱动学习路径。
  - **组成**：A 是 B 的一部分。
  - **对比**：容易混淆、值得放在一起看。
  - **类比 / 同构**：不同领域里结构相同的想法（如“熵”在热力学和信息论里）。这类跨领域连接最有意思，最适合做传播。
  - **应用**：A 在 B 场景里被用到。
- **去重**：新地图生成后，先按规范名和别名匹配已有知识点；匹配不上的，让模型在候选里判断是不是同一个；拿不准的进管理后台人工合并。
- **两种视图**：
  - 领域内：2D 技能树，看路径和点亮进度（学习时用）。
  - 全站：沿用 ReadWise 的 3D 星图，按领域聚成星团（逛和传播时用）。
- **和 ReadWise 打通**：知识点页底部“想深入，读这本书”，链到 ReadWise 里讲到同一概念的书；ReadWise 书页也可以反链“书里的这个概念，在 LearnWise 有一页”。这是跨产品的事，交给主 agent。

## 5. 技术方案

**Python FastAPI + SQLite**，和 SaveWise、InvestWise 同一类技术栈；后台生成任务用独立 worker 进程；模型走 OpenAI 兼容接口；systemd + Caddy 部署。页面用服务端模板 + 原生 JS，不引入前端框架和境外 CDN。代码自己写，不从 ReadWise 复制。

### 生成流程

```
领域名 + 目的 ──► 联网检索（博查）──► 资料评估
                        ▼
              生成领域地图 JSON ──► 校验（无环、前置存在、节点数）──► 质检 ──► 知识点去重入库
                        ▼
      用户点开某个知识点 × 档位（没有就排队生成；热门的预生成）
                        ▼
      检索该知识点资料 ──► 生成学习页 JSON ──► schema 校验 ──► 质检（事实、公式、题目答案）──► 内容安全 ──► 入库渲染
                        ▼
      可选：播客稿 ──► 双人语音
运行时（每次用户操作调用，小模型）：诊断题判分、费曼打分、问老师
```

### 数据（初稿）

```
domains        领域：名称、目的、分类、地图 JSON、首位生成者
concepts       知识点：规范名、别名、一句话定义
domain_nodes   领域 ↔ 知识点：阶段、顺序
edges          知识点之间的边：类型、理由、强度
pages          学习页：知识点、档位、页面 JSON、质检分、来源
progress       用户 × 知识点：状态（未学 / 学过 / 掌握）、闯关成绩
cards          复习卡：用户、题目、FSRS 参数、下次复习时间
usage          每次模型调用的 tokens、花费、用时（结构和 ReadWise 的 usage 表一致，总后台 core/collector 直接能采）
users          用户
```

### 成本估算（参照 ReadWise）

| 环节 | 估算 |
|---|---|
| 领域地图 | ¥0.3–0.8 / 个 |
| 学习页 | ¥0.8–1.5 / 页（比书页短） |
| 播客 | ¥1.5–2.5 / 集，只给热门知识点或按需生成 |
| 诊断、费曼打分、问老师 | ¥0.01–0.05 / 次，用小模型 |

一个 20 个知识点的领域全部生成约 ¥20–35（不含播客）。所以**按需生成**：用户学到哪生成到哪，第二个人学同一页时成本为零。

## 6. 分期

**第 0 步：样例页（写代码之前）**
先做 4 份关联性低的样例，覆盖三档，作为质量基准：`fixtures/*.json`，结构见 `docs/学习页结构.md`，`python3 scripts/render.py fixtures/*.json` 渲染到 `out/`。先用样例判断“30 分钟一页”的形态对不对，再写流水线。

**第 1 期 MVP**
账号（邮箱验证码登录；以后迁到主 agent 的统一账号）→ 输入领域 → 领域地图 → 自选水平 + 诊断 → 知识点学习页（知识块、回忆、闯关、费曼打分）→ 进度和地图点亮 → 公开领域库。

**第 2 期**
间隔复习和提醒邮件、积分、播客（模型判断值得才生成）、问老师。

**第 3 期**（全站知识星图已提前在 2026-10-22 上线：`/graph`，2D 力导向图，节点是知识点，跨领域联系分类比、应用、基础、对比四类）
和 ReadWise 互链、Boss 关、编程类知识点的在线代码运行、小程序。

## 7. 已定的决策（2026-10-22）

| # | 问题 | 决定 |
|---|---|---|
